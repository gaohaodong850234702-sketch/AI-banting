# 新手引导与声波验收

日期：2026-10-08。分支：`feat/onboarding-companion`。仅本地实现，未部署、未推送。

## 本次交付

- 新浏览器且没有个人记录时弹出首次邀请，可跳过。老用户保留原体验；右下角“使用帮助”可重新打开邀请。
- 播放 → 语音/文字记录 → 保存 → 从“我的思考”找回，以实际播放和持久化事件推进；刷新保留进度。
- 暖橙、浅金、鼠尾草绿的半透明丝带声波。待机缓慢流动；点击录音才复用原麦克风流，振幅与速度随本机实时输入变化，静音时回落。
- 录音结束、转文字、页面离开时释放音量分析节点。不会把麦克风接到扬声器，不会后台监听唤醒词。
- 手机紧凑提示、dialog 内引导、可读状态、减少动态效果、页面隐藏暂停绘制。
- 写入失败不显示保存成功；文字草稿保留，语音保留当前页录音块并可重试，重试不创建重复记录。

## 验证证据

`npm test`：31 项通过，包括首次/老用户/跳过状态、持久化成功条件、删除与刷新恢复、真实能量计算、分析节点释放，以及原有模型、引用和录音接口回归。

`npm run check`、`npm run build`：通过。

`scripts/verify-onboarding.mjs`：使用独立浏览器上下文，真实本地页面与音频播放；拦截模型配置为未启用，ASR 使用明确的测试响应。个人记录只写入该测试上下文，关闭后销毁；未调用模型工作流。

已通过：

1. 首次邀请和待机画面随时间变化。
2. 真实播放成功才推进；文字保存、打开本人新记录后完成。
3. 人为模拟浏览器配额不足：文字草稿保留；录音重试后只产生一条记录。
4. 刷新进度恢复、跳过不重复弹出、已有记录不强制引导。
5. 390px 和 320px 无横向溢出；提示底部不覆盖播放器。
6. 麦克风拒绝后可改用文字继续。
7. 真实 Web Audio 合成音频流通过与产品相同的分析器：静音约 0、低幅约 0.21、高幅约 0.88；不是给波形直接写测试音量。
8. 同一录音只申请一次流，停止后音轨结束；分析器自身不停止录音流。
9. 减少动态效果时两次截图保持一致；浏览器无未处理脚本错误。

截图位于 `.local/qa/onboarding/`，已人工查看桌面首次邀请、录音中状态与手机引导。

复现浏览器验证：先启动本地服务，再设置 `PLAYWRIGHT_MODULE` 为可用 Playwright 模块路径、`BROWSER_EXECUTABLE` 为 Chromium/Edge 路径，运行 `node scripts/verify-onboarding.mjs`。可用 `BANTING_URL` 改测试地址。

## 验证边界

本轮验证了真实 Web Audio 能量链路，未使用用户的物理麦克风录制真实讲话；硬件噪声、不同浏览器自动增益及 iOS 键盘表现仍需实际设备体验。没有重新验证云端模型的语义质量或真实 Whisper 转写准确率。

API 逐字段教程、历史关联/提问/阶段回顾的按场景提示仍属于下一阶段，不影响现有功能直接使用。
