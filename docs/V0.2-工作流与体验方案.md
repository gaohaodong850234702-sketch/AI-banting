# AI伴听 V0.2 全真模拟版

独立于 V0.1；端口 4318；浏览器存储 banting-demo-v2 / banting-media-v2。
真实公开播客 + 用户自己的记录 + 用户配置的大模型 API。没有预填个人经历或伪造模型回答。

## 四条工作流

1. 记录理解：先持久化用户原话，再转写触发前 90 秒原音频，结合上下文分析。明确区分原话、机器转写与模型推断。缺上下文时保留未知；保留立场的条件、犹豫和否定。输出结构化观点、疑问、行动、证据。
2. 历史关联：分析后检索真实旧记录；小规模记忆全部纳入（最多最近 80 条），超过则词项匹配加最近记录形成候选集。由模型做语义关系判断，并检查双方原话引用。允许没有关联。关联可确认/否定；否定保存为反馈。
3. 问题回忆：用户提问触发。检索候选，模型逐项回答并给证据引用；无记录不请求模型，不编造历史。声明实际检索范围。
4. 阶段回顾：用户手动生成，按选择的日期范围梳理反复问题、可能变化与未知。变化至少需要两个不同记录引用，不能把短期体验说成多年成长。

## 数据与控制

原始录音保存在浏览器 IndexedDB，记录、模型结果、反馈和执行状态在此版本的 localStorage。API Key 仅存本机服务的 .local/model-config.json（0600），浏览器不持久化也不能读回。调用前在设置页说明：用户文字及相关播客转写会发至所配置服务；保存并启用代表启用这些工作流。

共享提示词约束、任务提示词和输出验证分开。提示词版本、模型、执行时间和使用记录范围可查看。引用必须是输入原话的子串，未知 ID 拒绝。机械验证无法保证语义正确，提供纠错入口。

修订/删除记录使依赖的关联、问答和回顾失效，重新分析由用户触发或修订后触发。请求带内容快照，旧请求不得覆盖新内容；失败保留原话，可重试。无 API 配置时显示待配置，绝不降级为假 AI 结果。

## 体验路线

配置 API 并测试 → 听五期中的任意片段 → 每期留下自己的真实反应 → 检查理解与关联 → 在“问问过去的我”输入实际困惑 → 生成阶段回顾 → 标记理解/关联/回答是否有用。

节目时间、人数、招聘批次保留发布时背景，不作为当前招聘承诺。推荐收听点来自节目章节，不是逐字文稿。记录触发时由本机 Whisper 获取真实片段上下文，ASR 可能有误。

## 验证

需要验证：原版哈希未改变、版本/存储隔离、五期实际音频可播放和定位、真实片段 ASR、无密钥的诚实状态、API 兼容契约、引用校验、删除/修订失效、错误重试、手机可用。实际模型语义质量需用户配置 API 后体验，不以模拟服务通过替代。
